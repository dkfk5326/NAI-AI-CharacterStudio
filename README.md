# NAI-AI-CharacterStudio

[한국어](README.md) · [English](README.en.md)

**로컬 LLM과 캐릭터·장면을 논의하고, NovelAI에 사용할 캐릭터 프롬프트를 작성·수정하는 작업 공간입니다.** 한국어로 장면과 인물을 설명하면 영어 프롬프트 후보를 만들고, 인물별로 편집·복사할 수 있습니다. 채팅과 프롬프트 편집을 같은 화면에서 진행합니다.

이미지 생성기는 아닙니다. 완성한 프롬프트를 NovelAI에 직접 붙여 넣어 사용합니다. NovelAI 로그인·결제·이미지 생성 API를 호출하지 않으며, NovelAI의 공식 제품이나 제휴 서비스가 아닙니다.

저장소: [dkfk5326/NAI-AI-CharacterStudio](https://github.com/dkfk5326/NAI-AI-CharacterStudio)

## 주요 기능

- **캐릭터 프롬프트 작성:** 외형·의상·표정·자세·행동과 인물 간 관계를 입력하고, 결과 후보를 비교·수정합니다.
- **작업 공간 채팅:** 잡담, 캐릭터 설정, 이야기, 구도·조명·포즈를 논의합니다. 현재 캐릭터·장면·선택 결과를 참고하도록 설정할 수 있습니다.
- **대화·결과 관리:** 사용자와 모델 메시지의 수정·삭제, 대화 이름 변경과 삭제, 생성 결과 이름 변경과 개별·전체 삭제를 지원합니다.
- **대화 프롬프트 편집:** 브라우저에서 모델의 역할·말투·답변 방식을 정하는 기본 지시문을 편집합니다.
- **LLM용 NAI 가이드북:** 생성·재작성·채팅 요청에 관련 문법과 모델 제약을 참고 자료로 제공합니다.
- **선택적 태그 DB:** Danbooru 기반 SQLite DB를 연결하면 태그 탐색·자동완성·근거 확인을 사용할 수 있습니다.
- **로컬 저장:** 프로젝트, 결과, 수정본, 설정을 저장합니다. 프로젝트 JSON 내보내기와 가져오기를 지원합니다.

UI와 기본 대화 언어는 한국어입니다. 영어 README 제공과 별개로 영어 UI는 제공하지 않습니다.

## 설치

### 요구 사항

- Python **3.12 또는 3.13**
- Node.js **22.12 이상**과 npm
- Git 또는 GitHub의 **Code → Download ZIP**
- 실제 생성·채팅을 사용할 경우: 모델이 로드된 **llama.cpp 또는 LM Studio 로컬 서버**

모델·DB가 없어도 모의 모드로 입력·생성 예제·편집 흐름을 확인할 수 있습니다. 실제 모델의 메모리 요구량과 속도는 모델·양자화·장비에 따라 달라집니다.

이 저장소는 **소스 배포**입니다. Windows 실행 파일, Python 부트스트랩, 모델 가중치, 태그 DB는 포함하지 않습니다. 아래 절차로 실행하며, 소스 ZIP에서 `set_up.exe`를 실행하는 방식이 아닙니다.

### 1. 소스 받기

```sh
git clone https://github.com/dkfk5326/NAI-AI-CharacterStudio.git
cd NAI-AI-CharacterStudio
```

ZIP을 받았다면 압축을 풀고 `README.md`가 있는 폴더에서 터미널을 여세요.

### 2. Python 환경 만들기

```sh
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

macOS / Linux:

```sh
source .venv/bin/activate
```

### 3. 의존성 설치와 화면 빌드

```sh
python -m pip install -r requirements.lock
npm --prefix frontend ci
npm --prefix frontend run build
```

### 4. 앱 실행

```sh
python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

브라우저에서 **http://127.0.0.1:8000**을 엽니다. 서버를 실행한 터미널은 열어 두고, 종료할 때 `Ctrl+C`를 누릅니다. 다음 실행부터는 가상 환경을 활성화하고 4번 명령만 실행하면 됩니다. 프런트엔드 소스를 업데이트했다면 3번의 npm 설치·빌드를 다시 실행하세요.

## 실제 LLM 연결

1. llama.cpp 또는 LM Studio에서 사용할 모델을 로드하고 로컬 API 서버를 시작합니다.
2. 앱의 **설정**에서 실행 모드를 **실제 로컬 모델**로 변경합니다.
3. **추론 어댑터**를 해당 서버로 선택하고 **로컬 서버 주소**에 `/v1`까지 포함한 주소를 입력합니다. 예: `http://127.0.0.1:8080/v1`. 포트는 실제 서버 설정과 일치해야 합니다.
4. 필요하면 모델 ID와 로컬 서버 API 키를 입력하고 **설정 저장 → 저장된 연결 확인**을 누릅니다.
5. 생성 기능에는 구조화된 JSON 출력이 필요하므로 **JSON 제약 출력 시험**으로 지원 여부를 확인합니다. 채팅은 일반 텍스트 응답을 사용합니다.

내장 모델 프로필의 출처·파일·리비전은 [config/models.yaml](config/models.yaml)에 있습니다. 앱 연결 설정이 이미 실행 중인 외부 서버에 모델을 자동으로 로드하지는 않습니다. 모의 모드에서는 실제 채팅 응답을 생성하지 않습니다.

## 사용법

### 캐릭터 프롬프트 만들기

1. **작업 공간**에서 **2인 예제 불러오기**로 시작하거나 장면 설명과 캐릭터 카드를 작성합니다.
2. 대상 NAI 모델을 선택하고 캐릭터별 외형·의상·행동을 입력합니다. 인물 간 주체·대상을 고정하려면 관계를 작성합니다.
3. **프롬프트 생성**을 누르고 후보가 완성될 때까지 기다립니다. 인원이 많아 문맥 한도를 넘으면 **묶음 생성**을 사용합니다.
4. 결과의 Character Prompt와 Undesired Content(UC)를 직접 수정하고 각 복사 버튼으로 가져갑니다. 복사에는 현재 수정본이 사용됩니다.
5. NovelAI의 해당 캐릭터 프롬프트·UC 칸에 붙여 넣습니다. 베이스 프롬프트나 이미지 생성 설정은 NovelAI에서 별도로 설정합니다.

### 작업하면서 대화하기

작업 공간 옆 **작업 채팅**에서 메시지를 보냅니다. **현재 캐릭터·장면·선택 결과 참고**를 켜면 현재 작업 정보가 함께 전달됩니다. 끄면 작업 정보 없이 대화합니다.

결과의 **이 결과를 채팅에서 검토**로 수정 방향을 논의하고, 모델 답변의 **장면 입력에 추가**로 답변을 입력에 가져올 수 있습니다. 채팅만으로 프로젝트가 자동 수정되지는 않습니다.

각 메시지의 **수정·삭제**와 **대화 관리**를 사용해 기록을 정리합니다. 수정 내용은 다음 요청부터 반영됩니다. 응답 중인 대화는 응답 또는 중단이 끝난 뒤 편집합니다. 생성 결과는 **생성 기록 관리**에서 이름 변경·삭제할 수 있으며, 프로젝트 저장 시 저장된 이력도 정리됩니다.

### 대화 모델의 지시문 바꾸기

**작업 채팅 → 대화 프롬프트**에서 역할·말투·답변 방식을 편집하고 **프롬프트 저장**을 누릅니다. 저장 내용은 모든 대화의 다음 요청부터 적용되고 진행 중인 요청은 기존 지시문을 유지합니다. **기본값 불러오기** 후에도 저장해야 적용됩니다.

기본 지시문: [prompts/chat-system.md](prompts/chat-system.md). 생성용 프롬프트와 별도로 관리합니다.

### LLM 참고 자료와 태그 DB

[knowledge/llm-guidebook.json](knowledge/llm-guidebook.json)은 **LLM이 참조하는 NAI 가이드북**입니다. 설정의 **LLM 프롬프트·참고 자료**에서 편집할 수 있습니다. 사용 목적에 맞는 절이 자동 선택되며, 실제 모델의 동작을 보장하는 자료는 아닙니다.

태그 검색은 선택 기능입니다. [DB 출처](docs/SOURCES.md)의 SQLite 파일을 별도로 준비하고 **설정 → 태그 데이터베이스**에 파일의 절대 경로를 입력한 뒤 **해시·스키마 확인 후 연결**을 누릅니다. DB 원본은 읽기 전용으로 사용합니다. DB를 이 저장소에서 재배포하지 않습니다.

### 저장과 다시 열기

입력 초안과 대화는 같은 브라우저의 로컬 저장소에 보관됩니다. **프로젝트 저장**은 현재 프로젝트를 서버의 `data` 폴더에 저장하며, **프로젝트** 메뉴에서 다시 열 수 있습니다. **내보내기**로 프로젝트 JSON을 저장할 수 있습니다. 브라우저 저장소를 지우면 로컬 대화·초안이 사라질 수 있습니다.

앱 서버는 로컬 사용을 전제로 합니다. 기본 실행 주소는 `127.0.0.1`입니다.

## 문제 해결

| 증상 | 확인할 내용 |
| --- | --- |
| 화면이 열리지 않음 | 서버 실행 여부와 터미널 오류를 확인하고 `npm --prefix frontend run build` 후 새로고침합니다. |
| 업데이트 후 빈 화면 | `Ctrl+F5`로 새 화면 파일을 불러옵니다. |
| 채팅을 보낼 수 없음 | 실제 로컬 모델 모드, 서버 주소, 모델 로드 상태를 확인합니다. |
| 생성 JSON 오류 | 연결된 모델과 서버의 JSON 제약 출력 지원을 확인합니다. |
| 문맥 한도 초과 | 요청 길이·참고 정보를 줄이거나 묶음 생성을 사용합니다. 서버의 실제 문맥 한도와 앱 설정이 일치해야 합니다. |
| 태그 검색 없음 | DB 경로와 연결 상태를 확인합니다. DB 없이도 일반 편집은 가능합니다. |

## 개발 및 테스트

```sh
python -m pip install -r requirements-test.lock
python -m unittest discover -s tests
npm --prefix frontend test
npm --prefix frontend run build
```

Python 테스트 전에 프런트엔드를 한 번 빌드해야 합니다. 개발 화면은 `npm --prefix frontend run dev`로 실행하며 백엔드도 별도로 켜 둡니다. 자동 테스트는 실제 Windows GPU·모델 품질 검증을 대체하지 않습니다.
